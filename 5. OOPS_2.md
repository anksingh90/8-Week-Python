- It is a method belongs to Class rather than instance of Class.
- It behaves like a normal function that is placed inside a class for organizational purposes.

## 8. Property Decorators

Def - A property decorator lets you control how a variable is accessed, changed, or deleted, while still allowing users to treat it like a normal attribute.

- Think of it this way :  
    - Without a property: You access data directly.
    - With a property: Python secretly calls a method whenever you read or change the data.

Q : Why Do We Need Properties ?
- Suppose you have a student's marks.

```python
class Student:
    def __init__(self):
        self.marks = 80

s = Student()
print(s.marks)      # Output : 80
s.marks = -50       # changing marks to invalid value : -50
print(s.marks)      # Output : -50
```

Using Decorator, we allow Python to first check the validation then allow it to change the values of Marks.

```python
class Student:
    def __init__(self):
        self._marks = 80

    @property
    def marks(self):
        return self._marks

    @marks.setter
    def marks(self, value):
        if 0 <= value <= 100:
            self._marks = value
        else:
            print("Invalid Marks")

s = Student()

print(s.marks)

s.marks = 95
print(s.marks)

s.marks = -20
```

Types of Property Decorators : 
1. @property (Getter) : Used to read a value.

```python
class Student:

    def __init__(self):
        self._name = "Ami"

    @property           # @property : (Getter) - To read value from attribute
    def name(self):
        return self._name

s = Student()
print(s.name)
```

2. @name.setter (Setter) : Used to change a value.

```python
class Student:

    def __init__(self):
        self._name = "Ami"

    @property           # reading value from _name
    def name(self):
        return self._name

    @name.setter        # changing value to value from main()
    def name(self, new_name):       # method gets invoke when a new value is assigned to method.
        self._name = new_name

s = Student()

s.name = "Amy"          # setter gets invoked
print(s.name)           # Output : Amy
```

3. @name.deleter (Deleter) : Used when deleting a value.

```python
class Student:

    def __init__(self):
        self._name = "Ami"

    @property
    def name(self):
        return self._name

    @name.deleter
    def name(self):
        print("Name Deleted")
        del self._name

s = Student()
del s.name          # deleted gets invoked, Output : Name Deleted
```

## Easy Way to Remember

Suppose the property is `marks`.

| Decorator | Purpose | How You Use It | What Python Calls Behind the Scenes |
|-----------|---------|----------------|-------------------------------------|
| `@property` | Read (Get) the value | `print(s.marks)` | `s.marks()` (getter method is called automatically) |
| `@marks.setter` | Change (Set) the value | `s.marks = 90` | `marks.setter(90)` (setter method is called automatically) |
| `@marks.deleter` | Delete the value | `del s.marks` | `marks.deleter()` (deleter method is called automatically) |

> **Memory Trick:**  
> - **Getter** → Read the value (`print(s.marks)`)  
> - **Setter** → Change the value (`s.marks = 90`)  
> - **Deleter** → Delete the value (`del s.marks`)

## 9. Class Inheritance with isinstance() method

Q : What is isinstance()?
Ans : The isinstance() function checks whether an object belongs to a particular class or any of its parent (base) classes.

Syntax : 
```python 
isinstance(object, class_name)
```
- object → The object to check.
- class_name → The class you want to compare against.
- Returns: True or False.

Example - 
```python
class Student:
    pass

s1 = Student()

print(isinstance(s1, Student))      # Output : True
```

Using Inheritance - 
```python
class Animal:
    pass

class Dog(Animal):
    pass

d1 = Dog()

print(isinstance(d1, Dog))          # Output : True
print(isinstance(d1, Animal))       # Output : True
```

Q : Why is it used ?
- isinstance() used to check that an object is of the expected type before performing an operation.

For example - 

```python
class Student:      # Students needs to take exam
    pass

class Teacher:      # Teachers will act as Proctor
    pass

def take_exam(person):      # accepting instance of class
    if isinstance(person, Student):     # if object is of class Student, Response : True
        print("Exam Started")
    else:
        print("Only students can take the exam")

s = Student()       # instance created
t = Teacher()

# access method - take_exam to confirm if user is allowed to take example
take_exam(s)        # Student is allowed to take exam - Output : Exam Started
take_exam(t)        # Teacher are not allowed to take exam - Output : Only students can take the exam
```

## 10. Multiple Inheritance

Q : What is Multiple Inheritance?
- Multiple Inheritance is a type of inheritance where one child class inherits properties and methods from two or more parent classes.

- In simple words:
    - One child class can have multiple parents.

```python
class Parent1:
    pass

class Parent2:
    pass

class Child(Parent1, Parent2):
    pass
```

```text
Parent1      Parent2
     \        /
      \      /
       \    /
        Child
```

1. Basic Multiple Inheritance

```python
class Father:
    def bike(self):
        print("Father owns a Bike")

class Mother:
    def car(self):
        print("Mother owns a Car")

class Child(Father, Mother):
    pass

c = Child()

c.bike()        # Output : Father owns a Bike
c.car()         # Output : Mother owns a Car
```

2. Constructors (__init__())

```python
class Father:
    def __init__(self):
        print("Father Constructor")

class Mother:
    def __init__(self):
        print("Mother Constructor")

class Child(Father, Mother):
    pass

c = Child()     # Output  ??
```

> **What actually happens:** Since `Child` doesn't define its own `__init__`, Python looks it up using MRO (Method Resolution Order) — left to right through the parents listed in `class Child(Father, Mother)`. It finds `Father`'s `__init__` first and calls only that one. `Mother`'s `__init__` is **not** called automatically. This is exactly why multiple inheritance needs careful handling — nothing merges by magic, you often have to call both parents' logic deliberately.

### 🧪 Practice — Multiple Inheritance

**Mental model reminder:** Multiple inheritance is one child with two family trees. Python has to decide, in a strict left-to-right order (MRO), whose rules to follow first when there's a clash. This matters hugely for database work — if both parents want to save something, *you* must make sure both actually happen; Python won't do it for you automatically.

```python
    generate_report_card(s1)

    s1.marks = 150          # invalid → rejected, nothing saved

    t1 = Teacher("Mr. Sharma", "Physics")
    try:
        generate_report_card(t1)
    except TypeError as e:
        print(e)
```

## Quick Summary

| Concept | Core Idea | In This Practice |
|---|---|---|
| **Static Method** | Belongs to the class, not any instance — no `self` needed | Validators, formatters, and shared DB connection helpers |
| **Property Decorators** | Control access to an attribute while it still looks like a normal variable | Validated setters before DB writes, computed properties never stored, soft-delete deleters |
| **`isinstance()`** | Confirms an object's real type, including its whole inheritance chain | Type-safe save routing, bulk-insert filtering, diamond-chain table routing |
| **Multiple Inheritance** | One child class, two or more parent classes | Mixins for saving + logging, cooperative `super()`, the diamond problem solved via MRO |
